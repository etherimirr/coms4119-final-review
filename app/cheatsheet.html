COMS 4119 · APP & TRANSPORT

Layering & Encapsulation

  • Application — Message. HTTP · DNS · SMTP / IMAP · FTP · DHCP · RTP · BGP · BitTorrent
  • Transport — Segment (TCP & UDP). TCP: reliable, ordered. UDP: fast, no conn, no reliability.
  • Network — (IP) Datagram. Direct-over-IP: ICMP, OSPF.
  • Data Link — Frame. MAC addr (Ethernet / 802.11). Direct-over-link: ARP.
  • Physical — Bits

Encapsulation: lower layer wraps upper PDU. Demux up: Ethertype → IP proto → port → app.

Transport map: HTTP / SMTP / IMAP / FTP / BGP / BitTorrent → TCP · DNS (default) / DHCP / RTP → UDP · OSPF / ICMP → raw IP · ARP → link

Packet vs Circuit Switching

  • Circuit: establish → reserve → send (no dst addr) → tear down. Mux: TDM / FDM
  • Packet: hdr-tagged → independent forward → store-and-fwd → reassemble. Best-effort (may lose / corrupt / reorder)
Circuit ✅Circuit ❌
Guaranteed BW · simple abstraction · simple forwarding · low per-pkt overheadWasted BW on bursty · blocked connections · set-up delay · per-conn state

vs Packet: great for bursty (resource sharing, no setup); congestion → buffer overflow → delay/loss. Internet picks packet.

Delays & Performance mid Q2 Q4

  • Transmission = L/R (size/bandwidth)
  • Propagation = d/v (light 3·10⁸ m/s, sound 1.5 km/s in water)
  • Queuing: depends on load
  • End-to-end (1 pkt) = Σ(L/R + d/v) per link + queue
  • Pipelined N pkts: 1st full path + (N−1)·bottleneck L/R
  • Bottleneck = link with max L/R = min R (NOT propagation!)
  • Propagation paid once for 1st pkt (no stack)
  • Throughput = min(R) = bottleneck rate
📝 mid Q2 要诀: Store-and-forward 链路链：第 1 个包 = Σ 每段 L/R，后面的包 = 瓶颈段 L/R 累加。

BDP — Bandwidth-Delay Product

BDP = R · RTT (bits in pipe)
  • "How many bits fit in the pipe at once"
  • Window size must ≥ BDP to keep pipe full
  • Example: 30 Kbps × 80 ms = 2400 bits

Stop-and-Wait Utilization

U = T_trans / (T_trans + 2·T_prop)
  • T_trans = L/R
  • ×2 T_prop in denom (round-trip)
  • L small / RTT large → U → 0 → need sliding window
  • Ex: 2 Kb @ 40 Kbps · 30 m acoustic + 3 km air → U≈0.54; @ 200 b → 0.11
📝 mid Q5 要诀: Stop-and-wait U 公式：分子 transmission，分母 transmission + 2·prop。包小 / RTT 大 → U 暴跌 → 必须用滑窗。

Sliding Window

  • Window [base, base+N): send any unACKed in window
  • ACK → base slides forward
  • Stop-and-wait = window of 1
  • Window ≥ BDP → full pipe

HTTP Persistence & Cache

  • Non-persistent (1.0): new TCP/obj → 2 RTT/obj
  • Persistent (1.1): reuse TCP for all objs to same server
  • Pipelining: send next req before prev resp
  • Web Cache (proxy): cuts RTT + outbound BW
  • Conditional GET: If-Modified-Since → 304 (no body) if same, else 200 + body

HTTP Cookies

  • HTTP stateless → cookies add per-user state
  • Flow: Set-Cookie in resp → client file → Cookie in next req → server DB
  • Uses: cart · auth · ad tracking

HTTP/2 + HTTP/3

  • 1.1 HOL: FCFS → small obj waits behind large
  • 2: single TCP · object frames · priority · push · interleave frames mitigates HOL
  • 2 limit: 1 TCP → 1 lost pkt stalls all objs
  • 3: over UDP (QUIC) · per-obj CC + recovery · TLS default

Video / DASH

  • Server: chunks at multiple bitrates
  • Client picks next bitrate by observed BW
  • HTTP-based → any CDN works

Sockets

  • UDP: 1 socket total (no conn)
  • TCP: 1 welcome + N conn = N+1 sockets
  • UDP demux: (src IP, src port)
  • TCP: accept() → new socket; welcome stays

DNS

  • Hierarchy: local resolver → root → TLD (.com, .edu) → authoritative
  • Recursive ("resolve for me") vs iterative ("tell me next hop")
  • Local resolver usually iterative
  • RR: A (IPv4) · AAAA (IPv6) · NS · MX · CNAME
  • UDP/53 short query; TCP fallback for large

P2P File Distribution

CS: T = max(NF/U_s, F/d_min)
P2P: T = max(F/U_s, F/d_min, NF/(U_s + ΣU_i))
  • CS: T grows linearly with N (server uploads N copies)
  • P2P: T grows slowly with N (collective upload also scales)
  • Small N: tied · Large N: P2P wins
  • Ex: 1 GB / 100 u, 40 Mbps server → CS 20000 s vs P2P ≈ 1000 s
📝 mid Q7 要诀: Client-server 时间随 N 线性增（server 是瓶颈），P2P 时间随 N 微增（集体带宽也增）。N 大时 P2P 优势越来越明显。

BitTorrent & DHT

  • Rarest first: pick chunks scarce in swarm
  • Tit-for-tat: upload to those who upload to you
  • Optimistic unchoke: ~30 s gift BW to new peer (explore)
  • DHT: distributed hash table replaces central tracker

TCP Segment Format

  • Src/dst port (16 b each)
  • Seq # = first byte (32 b) · ACK # = next expected (32 b)
  • HLEN · flags: SYN/FIN/ACK/RST/PSH/URG/CWR/ECE
  • rwnd (16 b) — flow control
  • Checksum (16 b) · urgent ptr

TCP 3WHS & 4-Way Close

  1. C→S: SYN seq=x
  2. S→C: SYN-ACK seq=y, ack=x+1
  3. C→S: ACK seq=x+1, ack=y+1

Close = 4-way (FIN/ACK each dir). TIME_WAIT 2·MSL → avoid stray pkts in next conn.

What Can Go Wrong in Data Transmission

  1. Bit errors → checksum
  2. Duplicates → seq # dedupe
  3. Losses → timer + retransmit
  4. Delay → still need in-order delivery
  5. Out-of-order → seq # reorder

Map: checksum (1) · ACK (1, 3) · seq # (2, 5) · timer (3, 4) · rcvr buffer (5)

RDT Evolution (1.0 → 3.0)

  • 1.0: perfect channel (useless)
  • 2.0: + ACK/NAK + checksum → bit errors
  • 2.1: + seq # → ACK corruption
  • 2.2: NAK-free (ACK + last good seq)
  • 3.0: + timer → losses (= stop-and-wait)
  • Pipelined: GBN / SR

TCP Reliable Mechanisms

RTO = EstRTT + 4·DevRTT
  • EstRTT EWMA, α = 0.125
  • DevRTT EWMA of |Sample − Est|, β = 0.25
  • Fast retransmit: 3 dup ACKs → immediate resend
  • After timeout: RTO doubles (exp backoff)

TCP Flow Control + SR Buffer Trap

  • Rcvr advertises rwnd in every ACK
  • Sender inflight ≤ min(cwnd, rwnd)
  • SR rcv buffer holds out-of-order → hold until in-order delivery
  • Trap: pkt 1 lost + 2,3,4 fill buf → can't release → pkts 5+ dropped
  • Ex: 10 pkts, buf=4, pkt 1 lost → retransmit 7 pkts (1 + 5–10)
  • rwnd must ≤ buf size
📝 mid Q6 要诀: Receive buffer 不是简单容量计数，是『等齐才交付』占用。Advertised window 必须 ≤ buffer，否则会丢包。

TCP cwnd

  • LastByteSent − LastByteAcked < cwnd
  • rate ≈ cwnd / RTT
  • inflight ≤ min(cwnd, rwnd)
throughput ≈ cwnd / RTT

TCP CC FSM exam

Loss detection → recovery: Timeout ⇒ cwnd=1 + slow start; 3 dup ACK ⇒ cwnd/=2 + fast recovery → CA.

  • Slow start: cwnd=1; each ACK cwnd += MSS (×2/RTT)
  • cwnd > ssthresh → Congestion avoidance (+1 MSS/RTT)
  • 3 dup ACKs in CA → ssthresh=cwnd/2, cwnd=ssthresh+3 → Fast recovery; new ACK → back to CA (cwnd=ssthresh)
  • Timeout any state → ssthresh=cwnd/2, cwnd=1 → slow start

Trap: FR + new ACK → CA, NOT slow start.

AIMD Fairness exam

  • +a → both move up 45° (efficiency line)
  • ×b → toward origin, ratio kept
  • Spiral converges to x1=x2 ∩ x1+x2=1
  • Only AIMD → both fairness + efficiency
avg cwnd = 3W/4 → R = 3W/(4·RTT)

Subnet

Link State Routing (LS) — 4 steps

  1. Each node knows local link state (direct neighbors + costs)
  2. Flood link state to all routers
  3. Each node now knows full topology
  4. Run Dijkstra → shortest paths

"Big mouth": flood everyone. Global view per node. Used by OSPF, IS-IS.

Distance Vector Routing (DV)

  • Each node tells only neighbors its DV
  • Update via Bellman-Ford: D_x(y) = min_v {c(x,v) + D_v(y)}
  • DV changes → notify neighbors → eventually converges
  • Async, self-stopping: no change → no msg

"Whisper": only tell neighbors. Local view per node. BGP is a path-vector variant.

Dijkstra (LS)

D(v) = min(D(v), D(w) + c(w, v))
  1. Init: N' = {u}; D(v) = c(u, v) or ∞
  2. Pick w ∉ N' with min D(w); add to N'
  3. Relax all neighbors of w
  4. Repeat until N' = all nodes

O(n²) · heap → O(n log n). Msg complexity O(n²).

Bellman-Ford (DV)

D_x(y) = min_v ∈ N(x) [c(x, v) + D_v(y)]
  • Each node holds table[dst][via-neighbor]
  • DV = row-min of table
  • On neighbor DV msg → update via BF; own DV changes → tell neighbors
  • Init: only direct neighbors filled; rest ∞ per-via column
  • BF takes min over neighbors, not sum
  • Convergence ≈ max-hop − 1 (sync, static, no CTI)

Count-to-Infinity + Poison Reverse

  • Link cost ↑ → stale DVs → +1/+1 spiral loop
  • Poison reverse: Z routes thru Y to X → Z advertises Z→X=∞ to Y
  • Fixes 2-node loops; not 3+ node loops
  • Cap loops with small "∞" (e.g. 16)

OSPF (intra-AS)

  • Open · link-state · Dijkstra
  • Flood LSAs over raw IP (no TCP/UDP, self-reliable)
  • Multi-metric weights (BW, delay)
  • Authenticated msgs
  • Hierarchy: area + backbone (area 0); ABR summarizes; border router → other AS

BGP (inter-AS) exam

  • Path vector over TCP
  • eBGP: between ASes · iBGP: within AS (propagate eBGP routes)
  • Msgs: OPEN / UPDATE / KEEPALIVE / NOTIFICATION
  • Advertise = (prefix, AS-PATH, NEXT-HOP)
  • AS-PATH contains own AS → reject (loop)
  • Route select: 1) local pref → 2) shortest AS-PATH → 3) closest NEXT-HOP (hot potato) → 4) others

BGP Policy

⚠️ Trap: BGP does NOT always pick shortest AS-PATH — it is policy-based. If a neighbor AS refuses to forward, traffic must take a longer path.

  • Export: choose whom to advertise to
  • Import: choose whose route to accept
  • Provider only carries traffic to/from customers; refuses transit between other ISPs
  • Columbia-CERN example: don't advertise CERN path to NYU → NYU can't route via Columbia
  • Customer-of-provider always gets advertised

Hot Potato Routing

Def: For a packet headed to another AS, the router forwards it to the border router with minimum intra-AS cost ("throw the hot potato out fast").
Why: each AS only minimizes its own traffic cost, ignoring how far the packet travels in other ASes.

  • Multi-exit to same dst → pick gateway with min intra-AS cost
  • 3rd tiebreaker in BGP route selection: closest NEXT-HOP
  • Locally optimal per AS, may not be globally shortest

Why Intra ≠ Inter exam

  • Policy: inter needs admin policy · intra = 1 admin
  • Scale: hierarchy shrinks tables (~1M BGP prefixes)
  • Perf: intra optimizes path · inter optimizes policy

SDN + OpenFlow

  • Controller computes flow tables, ships to switches via OpenFlow
  • Match + Action unifies router / switch / firewall / NAT / LB
  • Match: 11 fields (in-port · src/dst MAC, Ethertype, VLAN id+pri · src/dst IP, proto, ToS · src/dst port) — all wildcardable
  • Action: forward · drop · modify · to-controller
  • Priority resolves overlaps · counters track stats
  • Msgs C→S: features · configure · modify-state · packet-out
  • Msgs S→C: packet-in · flow-removed · port-status
  • Northbound API → apps · Southbound → switches

SDN — 4 Design Principles

  • ① Flow-based forwarding: match on 11-tuple, not just dst IP (generalized match)
  • ② Separate DP from CP: switch only does fast forwarding; controller makes all routing decisions
  • ③ External, centralized CP: a dedicated server runs the controller
  • ④ Programmable network: apps program network behavior via northbound API

→ Network shifts from purpose-built hardware to commodity switches + a centralized programmable controller.

Link Layer services

  • Framing (hdr + trailer)
  • Error detection/correction

Error Detection

  • Parity 1-bit: detects odd-bit errors only
  • 2D parity: detects + corrects single bit
  • Checksum: 16-b word sum w/o carry (TCP/UDP/IP)
  • CRC: R = D·2^r mod G; send (D, R); rcvr checks (D·2^r XOR R) mod G = 0
R = (D · 2^r) mod G (mod 2 = XOR)

CRC detects all burst errors ≤ r bits.

Slotted ALOHA derivation

S(p) = N · p · (1−p)^(N−1)
  • Max at p* = 1/N
  • S_max → 1/e ≈ 0.37 as N → ∞
  • Pure ALOHA (no slots): collision window 2× → S_max → 1/(2e) ≈ 0.18

CSMA / CSMA-CD

  • CS: listen before send
  • Collisions still happen due to propagation delay
  • CSMA/CD (wired): listen while sending → abort + jam + binary backoff
  • Wireless can't CD: TX power >> far-end RX → own RX deafened

CSMA/CD vs CSMA/CA exam

Key diff: wireless can't listen while TX (own TX dominates RX) → no detection, must avoid.

  • CSMA/CD (wired): listen during TX → detect collision → stop + jam + backoff
  • CSMA/CA (wireless): infer collision via missing ACK → backoff + retry
  • CD: send immediately when idle · CA: wait DIFS; ACK/CTS wait shorter SIFS
  • CD: min frame 64 B so collision heard before TX ends · CA: RTS/CTS for hidden terminal
  • CA ACKs every frame · CD doesn't ACK

CSMA/CD min frame size exam

L_min / R ≥ 2 · d_max / v
  • Detect collision before TX ends
  • 10 Mbps Ethernet → min 512 b, max cable 100 m
  • Binary backoff: after n collisions pick slot ∈ [0, 2ⁿ − 1]

Ethernet Frame

  • Preamble 7 B + SFD 1 B (clock sync)
  • Dst MAC 6 B + Src MAC 6 B
  • Type 2 B (0x0800 IP, 0x0806 ARP, 0x86DD IPv6)
  • Payload 46–1500 B
  • CRC 4 B

Modern Ethernet = switched, point-to-point, full duplex, no CSMA/CD.

Wireless ≠ Wired exam

  1. Time-varying channel: distance · mobility · environment
  2. Broadcast → interference from neighbors

These two drive all wireless MAC design.

Free-Space Pathloss

L = (4πd/λ)² = (4πdf/c)²
  • d = dist · λ = wavelen · f = freq · c = light speed
  • Higher f (smaller λ) → more loss
  • 5 GHz attenuates faster than 2.4 GHz · worse through walls

Real env: PL(d) = PL(d₀) + 10α · log(d/d₀) + X. α = 2 free · 2.7–3.5 urban · 4–6 indoor.

Propagation Modes

  • Reflection: object ≫ λ (walls, ground)
  • Diffraction: bends around edges (corners)
  • Scattering: object < λ (leaves, lamp posts) — hardest to model

Fading

  • Large-scale: avg drop w/ distance (pathloss + shadowing)
  • Small-scale: rapid swings in small area (multipath)
  • Mobility → small-scale fade

Multipath & Coherence Time

  • LOS + reflected paths arrive at diff times → ISI
  • Coherence time = how long channel response stays valid
  • Symbol period < coherence time

SNR / SINR

SNR_dB = 10·log₁₀(S/N) · SINR_dB = 10·log₁₀(S/(N+I))
  • Higher SNR → lower BER → higher mod/code rate
  • SINR adds interference from other senders

WiFi ranges

  • Transmission < Interference < Carrier sensing
  • Neighbors may interfere but not decode

CSMA's Fundamental Flaw (Wireless)

Key: CSMA = sender senses channel — but collision = at receiver.

  • Sender hears idle ≠ receiver can decode
  • Wireless attenuates w/ dist → sender + receiver see different channel
  • → Hidden Terminal (sender thinks idle, receiver collides)
  • → Exposed Terminal (sender thinks busy, receiver free)

Fix: shift decision from sender → receiver. ACK (CSMA/CA) + RTS/CTS (receiver claims channel).

Hidden Terminal exam

Def: node X outside sender A's range but inside receiver B's interference range. X hears idle → sends → collides w/ A at B.

  • Symptom: A transmits fine, B receives nothing
  • Equiv: A & B both transmit to middle C; A↔B too far to hear → collision at C

Fixes: CSMA/CA (ACK) + RTS/CTS (NAV). See those sections.

Exposed Terminal

  • X inside sender A's range (hears A) · X's target outside A's range
  • X needlessly defers → wasted parallelism
  • No clean CSMA/CA fix

Mnemonic: hidden = sender-OUT + recv-IN (should stop, doesn't). Exposed = sender-IN + target-OUT (defers, didn't need to).

⭐ lec23 p27 CSMA/CA — 三大机制拆解

RTS / CTS / NAV

  • A → RTS · B → CTS (carries NAV duration)
  • Hear RTS → quiet for ~CTS time
  • Hear CTS → quiet for full NAV
  • Solves hidden · NOT exposed

CSMA/CA full flow exam

  1. Carrier sense (physical + virtual NAV)
  2. Idle → wait DIFS → still idle → send
  3. Replies (CTS / ACK) wait SIFS (shorter, priority)
  4. Busy → after DIFS pick random backoff ∈ [0, CW]; decrement when idle, freeze when busy
  5. Backoff = 0 → send RTS
  6. No CTS → CW = min(2·CW, CWmax) (binary exp)
  7. Success → reset CW = CWmin

No collision detection: TX deafens own RX.

Backoff variants

  • Binary exp: aggressive reset → oscillation + unfair
  • MACAW: CW − 1 on success (linear decrease — "AIMD" of MAC)
  • Append CW to packet so peers track congestion
