End-to-End Principle

  • Complex functions go at endpoints, not in the network core
  • e.g. reliability: TCP at hosts, not per-hop
  • Drives many designs: best-effort IP, IPv6 (no router fragmentation), NAT controversy, RDT at L4
  • Cite: Saltzer et al. "End-to-End Arguments in System Design" (1984)

协议跑在哪一层 / 用 TCP 还是 UDP

  • TCP（可靠有序）: HTTP / HTTPS · SMTP · IMAP · POP3 · FTP · SSH · Telnet · BGP · BitTorrent · DNS（大响应回退）
  • UDP（快、无连接、无可靠性）: DNS（默认）· DHCP · RTP（实时音视频）· SNMP · TFTP · QUIC (= HTTP/3) · VoIP
  • 直接跑在 IP 上（不走 L4）: ICMP（ping / traceroute）· OSPF（IP protocol 89）· IGMP
  • 直接跑在 L2 上（不走 IP）: ARP（Ethertype 0x0806）· STP · LLDP

考点：『邮件用什么协议？SMTP / IMAP / POP3 都跑 TCP』『打开网页拿 IP 用 DNS over UDP』『查路由器到底走不走 TCP？OSPF 直接 IP，BGP 才用 TCP』。

Packet vs Circuit Switching

  • Circuit: source establish 连接 → 节点 reserve resources → send（无 dst 地址）→ tear down。复用：TDM（时分）/ FDM（频分）。
  • Packet: 切包带 header → 包独立 forward → 节点暂存 → dst 重组。Best-effort：可能 loss / corrupt / 乱序。
Circuit ✅Circuit ❌
Guaranteed BW · 简单抽象 · 简单 forwarding · 低 per-pkt overheadBursty 浪费 BW · Blocked connections · Set-up delay · Per-conn 状态

Delays & Performance mid Q2 Q4

  • Transmission = L/R (size/bandwidth)
  • Propagation = d/v (light 3·10⁸ m/s, sound 1.5 km/s in water)
  • Queuing: depends on load
  • End-to-end (1 pkt) = Σ(L/R + d/v) per link + queue
  • Pipelined N pkts: 1st full path + (N−1)·bottleneck L/R
  • Bottleneck = link with max L/R = min R (NOT propagation!)
  • Propagation paid once for 1st pkt; doesn't stack across N pkts
  • Throughput = min(per-link R) = bottleneck rate
📝 mid Q2 要诀: Store-and-forward 链路链：第 1 个包 = Σ 每段 L/R，后面的包 = 瓶颈段 L/R 累加。

BDP — Bandwidth-Delay Product

BDP = R · RTT (bits in pipe)
  • "How many bits fit in the pipe at once"
  • Window size must ≥ BDP to keep pipe full
  • Example: 30 Kbps × 80 ms = 2400 bits

Stop-and-Wait Utilization mid Q5

U = T_trans / (T_trans + 2·T_prop)
  • T_trans = L/R
  • Denominator has 2·T_prop — don't forget ×2 (round-trip)
  • When L small or RTT large → U collapses → need sliding window
  • Mid Q5: 2 Kb @ 40 Kbps over 30m acoustic + 3km air → U ≈ 0.54; @ 200 b → 0.11. Not good.
📝 mid Q5 要诀: Stop-and-wait U 公式：分子 transmission，分母 transmission + 2·prop。包小 / RTT 大 → U 暴跌 → 必须用滑窗。

Sliding Window

  • Sender maintains window [base, base+N)
  • Can send any unACKed packet in window without waiting
  • ACK arrives → base slides forward
  • Stop-and-wait = window of 1 (special case)
  • Window size ≥ BDP keeps pipe full

HTTP Persistence & Cache

  • Non-persistent (HTTP/1.0): new TCP per object; 2 RTT/obj
  • Persistent (HTTP/1.1): reuse TCP for all objects on same server
  • Pipelining: client sends next request before getting previous response
  • Web Cache (proxy): caches responses; cuts RTT + outbound BW; ISP often deploys
  • Conditional GET: client sends If-Modified-Since: <date>; server returns 304 Not Modified (no body) if unchanged, else 200 + body

HTTP Cookies

  • HTTP is stateless; cookies add server-side state per user
  • 4 parts: Set-Cookie header in response → cookie file on client → Cookie header in next request → server backend DB
  • First visit: server assigns ID (e.g. amazon: 1678); client sends ID on each subsequent request
  • Uses: shopping cart, auth state, ad tracking
  • GDPR: EU regulation forces explicit consent

HTTP/2 + HTTP/3

  • HTTP/1.1 problem: FCFS server response → small obj blocked behind large (HOL)
  • HTTP/2 (RFC 7540, 2015): single TCP; split objects into frames; client priority; can push unrequested objects; interleave frames mitigates HOL
  • HTTP/2 limit: still 1 TCP → TCP packet loss stalls all objects
  • HTTP/3: over UDP (QUIC); per-object congestion control + error recovery; adds TLS by default

Video / DASH

  • Video chunked at multiple bitrates
  • Client adapts based on observed BW
  • HTTP-based; any CDN works

Sockets mid Q1

  • UDP server: 1 socket only (no connection)
  • TCP server: 1 welcome + N connection = N+1
  • UDP distinguishes clients by (src IP, port) in datagram
  • TCP: each accept() returns a new socket; listening socket stays

DNS

  • Hierarchy: local resolver → root → TLD(.com,.edu) → authoritative
  • Recursive (resolve for me) vs iterative (tell me next hop)
  • Local resolver usually iterative
  • RR types: A (IPv4), AAAA (IPv6), NS, MX, CNAME
  • UDP 53 short query; falls back to TCP for large response

P2P File Distribution mid Q7

CS: T = max(NF/U_s, F/d_min)
P2P: T = max(F/U_s, F/d_min, NF/(U_s + ΣU_i))
  • CS time grows linearly with N (server uploads N copies)
  • P2P time grows slowly with N (collective upload also grows; denom increases)
  • Small N: tied. Large N: P2P wins.
  • Mid Q7: 1GB/100u, 40Mbps server → CS = 20000s; P2P ≈ 1000s. N ≥ 5 to outperform.
📝 mid Q7 要诀: Client-server 时间随 N 线性增（server 是瓶颈），P2P 时间随 N 微增（集体带宽也增）。N 大时 P2P 优势越来越明显。

TCP Segment Format

  • Src/dst port (16 b each)
  • Seq #: first byte of data (32 b)
  • ACK #: next expected byte (32 b)
  • HLEN, flags: SYN/FIN/ACK/RST/PSH/URG/CWR/ECE
  • Receive window rwnd (16 b) — flow control
  • Checksum (16 b), urgent ptr

TCP 3WHS & 4-Way Close

  1. SYN seq=x
  2. SYN-ACK seq=y, ack=x+1
  3. ACK seq=x+1, ack=y+1

Close = 4-way (FIN/ACK each direction). TIME_WAIT 2·MSL avoids stray old packets affecting new connection.

What Can Go Wrong in Data Transmission

RDT 协议要处理的 5 类问题（lec11）：

  1. Bit errors — 包内 bit 翻转 → checksum 检测
  2. Duplicated packets — 包重复到达 → seq # 去重
  3. Packet losses — 包丢失 → timer + retransmit
  4. Packet delay — 包延迟到达 → 仍要按序交付
  5. Packets arriving out of order — 乱序 → seq # 重排

机制对应：checksum (1) · ACK (1,3) · seq # (2,5) · timer (3,4) · receiver buffer (5)

RDT Evolution (1.0 → 3.0)

  • 1.0: perfect channel (useless)
  • 2.0: + ACK/NAK + checksum (handles bit errors)
  • 2.1: + seq # (handles ACK corruption)
  • 2.2: NAK-free (use ACK + last good seq)
  • 3.0: + timer (handles packet loss) — stop-and-wait
  • Pipelined: GBN / SR

TCP Reliable Mechanisms

  • Timeout retransmit: TimeoutInterval = EstRTT + 4·DevRTT
  • EstRTT = (1−α)·EstRTT + α·SampleRTT, α=0.125
  • DevRTT = (1−β)·DevRTT + β·|SampleRTT−EstRTT|, β=0.25
  • Fast retransmit: 3 dup ACKs → immediate resend
  • Exponential backoff after timeout (RTO doubles)

TCP Flow Control + SR Buffer Trap mid Q6

  • Receiver advertises rwnd in every ACK
  • Sender's inflight ≤ min(cwnd, rwnd)
  • SR receive buffer holds out-of-order packets — "hold until in-order delivery"
  • If pkt 1 lost + pkts 2,3,4 fill buffer → buffer can't release → pkts 5+ dropped
  • Mid Q6: 10 pkts, buffer=4, pkt 1 lost → retransmit 7 pkts (1 + 5–10)
  • Advertised window must ≤ buffer size, else overflow

📝 mid Q6 要诀: Receive buffer 不是简单容量计数，是『等齐才交付』占用。Advertised window 必须 ≤ buffer，否则会丢包。

TCP cwnd

  • Sender: LastByteSent − LastByteAcked < cwnd
  • rate ≈ cwnd / RTT bytes/sec
  • inflight ≤ min(cwnd, rwnd)
throughput ≈ cwnd / RTT

TCP CC FSM exam

Loss detection → recovery： Timeout ⇒ cwnd=1 + slow start； 3 dup ACK ⇒ cwnd/=2 + congestion avoidance。

  • Slow start: cwnd=1; each ACK cwnd += MSS (×2/RTT)
  • cwnd > ssthresh → Congestion avoidance (+1 MSS/RTT)
  • 3 dup ACKs in CA → ssthresh=cwnd/2, cwnd=ssthresh+3 → Fast recovery; new ACK → back to CA (cwnd=ssthresh)
  • Timeout any state → ssthresh=cwnd/2, cwnd=1 → slow start

Trap: FR + new ACK → CA, NOT slow start.

AIMD Fairness exam

  • +a moves both up 45° (efficiency line)
  • ×b scales toward origin (keeps ratio)
  • Spiral converges to x1=x2 ∩ x1+x2=1
  • Only AIMD achieves both fairness and efficiency
avg cwnd = 3W/4 ⇒ R = 3W/(4·RTT)

  • Common on wireless links
  • TCP misreads as congestion, halves cwnd → wireless throughput tanks
  • ECN helps: explicit signal instead of relying on loss

Link State Routing (LS) — 4 步

  1. 每 node 维护 local link state（直连邻居 + cost）
  2. 每 node flood 自己的 link state 给所有 router
  3. 每 node 学到整个网络拓扑
  4. 用 Dijkstra 算最短路径

"Big mouth"：广播全网。每 node 全局视角。代表：OSPF, IS-IS。

Distance Vector Routing (DV)

  • 每 node 只跟邻居说自己的 distance vector
  • 用 Bellman-Ford 方程更新：D_x(y) = min_v {c(x,v) + D_v(y)}
  • DV 变了 → 通知邻居 → 渐进收敛
  • 异步、自停：无变化无消息

"Whisper"：只跟邻居说。每 node 局部视角。代表：RIP（废）。BGP 是 path-vector 变种。

Dijkstra (LS)

D(v) = min(D(v), D(w) + c(w,v))
  1. N'={u}; D(v)=c(u,v) or ∞
  2. pick w ∉ N' with min D(w); add to N'
  3. relax all neighbors of w
  4. repeat until N' = all nodes

O(n²); heap → O(n log n). Msg complexity O(n²) too.

Bellman-Ford (DV)

D_x(y) = min_v∈N(x){ c(x,v) + D_v(y) }
  • Each node: table[dst][via neighbor]
  • DV = row-min of table
  • On neighbor DV msg → update via BF; if own DV changes → tell neighbors
  • Init: only direct neighbors filled, rest ∞ per-via column
  • BF takes min over neighbors, not sum
  • Convergence ≈ max-hop-count in shortest-path tree − 1 (sync, static, no CTI)

Count-to-Infinity + Poison Reverse

  • Link cost ↑: stale DVs cause loops, +1/+1 spiral
  • Poison reverse: if Z routes thru Y to X, Z advertises Z→X=∞ to Y
  • Solves 2-node loops; not 3+ node loops
  • RIP hop=16 means ∞

OSPF (intra-AS)

  • Open, link-state, runs Dijkstra
  • Flood LSAs directly over IP (no TCP/UDP — self-reliable)
  • Multi-metric weights (BW, delay)
  • Authenticated messages
  • Hierarchy: area + backbone (area 0); ABR summarizes; boundary router connects other AS

BGP (inter-AS) exam

  • Path vector, advertised over TCP
  • eBGP: between ASes; iBGP: within an AS (propagate eBGP routes)
  • Msgs: OPEN / UPDATE / KEEPALIVE / NOTIFICATION
  • Advertise = (prefix, AS-PATH, NEXT-HOP)
  • AS-PATH includes own AS → reject (loop)
  • Route select: 1) local pref 2) shortest AS-PATH 3) closest NEXT-HOP (hot potato) 4) others

Hot Potato Routing

Def: 对去往其他 AS 的包，router 把它转给 intra-AS cost 最小的 border router（"扔掉烫手山芋"）。
Why: 每个 AS 只关心 minimize 自己的 traffic cost，不在乎包出去后在别的 AS 走多远。

  • Multi-exit to same dst → pick gateway with min intra-AS cost
  • BGP route selection 第 3 步：tie-break 用 closest NEXT-HOP
  • 全局未必最短，但每个 AS 自己便宜（自私最优）

Error Detection

  • Parity 1-bit: detects odd-bit errors only
  • 2D parity: detects + corrects single bit
  • Checksum: 16-b word sum w/o carry (TCP/UDP/IP)
  • CRC: D·2^r mod G = R; transmit (D, R); receiver checks (D·2^r XOR R) mod G == 0
R = (D · 2^r) mod G (mod 2 = XOR)

CRC detects all burst errors ≤ r bits.

CSMA / CSMA-CD

  • CS: listen before send
  • Collisions still happen due to propagation delay
  • CSMA/CD (wired only): listen while sending; abort on collision; jam + binary backoff
  • Wireless can't CD: TX signal deafens own RX (功率差 10⁶+ 倍)

CSMA/CD vs CSMA/CA exam

关键差异：无线没法边发边听（自己 TX 盖过 RX 天线）→ 不能检测碰撞，只能避免。

  • CSMA/CD（Ethernet 有线）：发时继续监听 → 直接检测碰撞 → 立即停 + jam + backoff
  • CSMA/CA（WiFi 无线）：发完不知道碰没碰 → 靠接收方 ACK 推断 → 没 ACK 就 backoff 重发
  • CD 一旦空闲立即发；CA 要等 DIFS，ACK/CTS 等更短 SIFS（优先）
  • CD 用 min frame size 64B 保证发完前能听到碰撞；CA 用 RTS/CTS 防 hidden terminal
  • CA 每帧必 ACK；CD 不需要 ACK

CSMA/CD min frame size exam

L_min / R ≥ 2·d_max / v
  • Need to detect collision before tx ends
  • 10 Mbps Ethernet: min 512 bit, max cable 100 m
  • Binary backoff: after n collisions, pick slot ∈ [0, 2ⁿ − 1]

Free-Space Pathloss

L = (4πd/λ)² = (4πd·f/c)²
  • d = distance, λ = wavelength, f = freq, c = light speed
  • Higher f (smaller λ) → more loss
  • 5 GHz attenuates faster than 2.4 GHz; worse through walls

Real env: PL(d) = PL(d₀) + 10α·log(d/d₀) + X. α=2 free; 2.7–3.5 urban; 4–6 indoor.

Propagation Modes

  • Reflection: object ≫ λ (walls, ground)
  • Diffraction: sharp edges → bends around obstacles (corners)
  • Scattering: object < λ (leaves, lamp posts) — hardest to model

Fading

  • Large-scale: average drop w/ distance (pathloss + shadowing)
  • Small-scale: rapid swings in small area (multipath interference)
  • Mobility → small-scale fade

Multipath & Coherence Time

  • LOS + reflected paths arrive at different times → ISI
  • Coherence time = duration channel response stays valid
  • Symbol period must be < coherence time

SNR / SINR

SNR_dB = 10·log₁₀(S/N); SINR_dB = 10·log₁₀(S/(N+I))
  • Higher SNR → lower BER → higher mod/code rate possible
  • SINR adds interference from other senders

WiFi ranges

  • Transmission < Interference < Carrier sensing
  • Neighbors may interfere but not decode

CSMA 的根本缺陷（无线下）

关键洞察：CSMA 让 sender 听信道 — 但碰撞发生在 receiver。

  • Sender 听到信道空 ≠ receiver 收得到
  • 无线信号随距离衰减 → sender / receiver 看到的信道状态完全不一样
  • → 直接派生出 Hidden Terminal（sender 觉得空但 receiver 在碰撞）
  • → 也派生出 Exposed Terminal（sender 觉得忙但 receiver 其实闲）

解法（无线场景）：把决定权从 sender 移到 receiver — 显式 ACK（CSMA/CA）+ RTS/CTS（让 receiver 说话占信道）。

Hidden Terminal exam

例：A — C — B 一线，A 和 B 都对 C 发；A↔B 距离太远互相听不到 → 都觉得空闲 → 在 C 处碰撞。

  • X outside sender A's range, inside receiver B's interference range
  • X thinks idle → sends → collision at B
  • Symptom: A sends fine, B receives nothing

两个解法：
① CSMA/CA — 接收方对每帧显式 ACK；没 ACK = 推断碰撞，退避重发。
② RTS/CTS — A、B 都发 RTS 给 C；C 挑一个（say A）回 CTS，CTS 广播到所有人；A、B 都收到 CTS，只有拿到 CTS 的 A 发，B 静音（设 NAV）。

Exposed Terminal

  • X inside sender A's range (hears A), but X's own target is outside A's range
  • X needlessly defers → wasted parallelism
  • No clean CSMA/CA fix

Mnemonic: hidden = sender-out + recv-in (should stop but doesn't). Exposed = sender-in + target-out (defers but didn't need to).

RTS / CTS / NAV

  • A sends RTS → B replies CTS (with NAV duration)
  • Nodes hearing RTS quiet for ~CTS time
  • Nodes hearing CTS quiet for full NAV
  • Solves hidden, NOT exposed

CSMA/CA full flow exam

  1. Carrier sense (physical + virtual NAV)
  2. Idle → wait DIFS → still idle → send
  3. Replies (CTS/ACK) wait SIFS (shorter; priority over new contention)
  4. Busy → after DIFS, start random backoff [0, CW]; decrement when idle, freeze when busy
  5. Backoff=0 → send RTS
  6. No CTS → CW = min(2·CW, CWmax) (binary exp)
  7. Success → reset CW = CWmin

No collision detection: TX deafens own RX.

Backoff variants

  • Binary exp: too aggressive reset → oscillation + unfair
  • MACAW: CW −1 on success (linear decrease, "AIMD" of MAC)
  • Append CW to packet so peers track congestion
