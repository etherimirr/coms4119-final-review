1) (10 points) Answer the following questions regarding the Internet protocol stack:
      a) (4 points) How many layers does it have? What are the layers?
     b) (2 points) Do all the devices on the Internet have all the layers? Briefly explain why.
      c) (2 points) If one layer of the protocol stack has to be changed, do the layers below and above it have
         to be changed as well?
     d) (2 points) Which layer of the protocol stack has the least diversity?
   Answer: a) Five Layers: Application, Transport, Network, Link, and Physical.
   b) No, Devices only need layers up to their function domains. For example, routers don’t need Applica-
   tion/Transport Layers.
   c) No, Layered protocols follow modular design principle. One can change one layer without changing other
   layers.
   d) Network layer, all devices have to use the IP protocol for inter-connectivity.

         connections will be opened? if HTTP 1.1 is used, how many TCP connections will be opened?
     b) (3 points) HTTP itself is stateless, what mechanism does HTTP server use to keep track of client
         transaction history?
      c) (4 points) If an organization installs a HTTP proxy at the entrance of its network, what is the traffic
         impact on its Internet access link? what is the traffic impact on its internal network? what is the HTTP
         performance impact on its local users?
   Answer: a) HTTP 1.0: Five connections, one for the base html file, the other four for four embedded images;
   HTTP 1.1: One connection to download the base html file, as well as the four images
   b) HTTP uses Cookies to maintain user history.

   decrease the volume of the internal web traffic (even though web traffic will be concentrated on the proxy
   server now). If web objects are served from proxy, users will experience shorter response time.

4) (12 points) Please answer the following questions regarding reliable data transfer.
     a) (2 points) Why rdt 2.0 is not sufficient to deal with channel bit corruptions?
     b) (4 points) For rdt 2.1 to work, why does the sender have to assign a sequence number (either 0 or 1)
         to the packet it sends out?
     c) (4 points) For rdt 2.1 to work, does the receiver need to assign a sequence number to ACK/NAK it
         sends out? Briefly explain why or why not?
     d) (2 points) Can rdt 2.1 correctly handle packet losses?
   Answer:
   a) rdt2.0 cannot handle corrupted ack/nack
   b) if ack/nack is corrupted, the sender needs to retransmit the current packet, when the receiver receives the
   retransmitted packet, it needs to know whether this is a new packet or a retransmission, so the sender needs
   to use one bit to distinguish the current packet and the next packet.
   c) Since there is no packet loss, the ACK/NAK is always for the packet the sender just sent out, there is no
   need to add the sequence number to it.
   d) No, if the packet or the ACK/NAK is lost, the sender and receiver will be dead-locked.

5) (12 points) 100 users are interested in downloading a file with 100M bytes, suppose the file server’s upload
   bandwidth is 10Mbps (bits-per-second), each user has a download bandwidth of 10Mbps,
     a) (3 points) If all users download directly from the server, how long does it take for all users to finish
         the download of the file?
     b) (5 points) If all peers have upload bandwidth of 5Mbps, and they form a P2P file sharing network to
         download the file in P2P fashion, how long does it take for all peers to finish the download of the file?
     c) (4 points) Suppose another type of peers with 5Mbps download bandwidth and zero upload bandwidth
         also join the previous 100 users in the P2P file sharing network. We call this new type of peers free-
         riders. What is the maximum number of free-riders that the system can take before the download finish
         time on all peers (including the new peers) become twice as much as your answer in question b)?
   Answer:
   a) the total download demand is 100 ∗ 100M ∗ 8 bits, the server upload capacity is 10Mbps, so the total time
   for the server to complete the uploading is 100 ∗ 100M ∗ 8/10M = 8, 000 seconds; the time it takes for the
   slowest peer to download the whole file is 100M*8/10M=80 seconds;
   So the final answer is 8, 000 seconds.
   b) the time it takes for the server to send out one copy is 100M*8/10M=80 seconds;
   the time it takes for the slowest peer to download the whole file is 100M*8/10M=80 seconds;
   the total upload capacity in the system is 10M+100*5M=510M,
   the total download time is 100*100M*8/510M=800/5.1=156.87 seconds;
   the final completion time is max(80, 80, 133.3) = 156.87 seconds.
   c) The new complete time becomes 313.74 seconds, which is longer than the time the server sends out one
   copy, and the time for the slowest peer to finish download. Since the total upload capacity in the system
   does not change after the free-riders join, that means the total download demand doubles, i.e., the number of
   free-riders is the same as the existing peers, that is 100.

   rate from A to B is 10Mbits-per-second, the link transmission rate from B to C is 100Mbits-per-second, and
   the propagation delays on link AB and BC are both 20 milli-seconds, assuming there are no other packets
   in the network.
     a) (4 points) How long does it take to send a packet with size of 1 kilo-bytes from A to C?
     b) (4 points) If A uses stop-and-wait transport protocol to send data to B reliably, what are the link
         utilizations on AB and BC, respectively? You can ignore the transmission delay of ACK/NAK packets,
         and the propagation delays on each link is symmetric on both directions.
     c) (4 points) If A uses a sliding-window based transport protocol to send data to B reliably, what is the
         highest throughput A can achieve? what is the minimum window size to achieve the highest throughput?
         what are the link utilizations on AB and BC, respectively?
   Answer: a) packet transmission time on AB=1,000*8/10M=0.8 ms, on BC=1,000*8/100M=0.08 ms; the total
   time = 0.8+0.08+20*2=40.88 ms;
   b) the round-trip time is 40.88+40=80.88ms, with stop-and-wait, one packet is transmitted on each link
   every one round trip time, the throughput is 8, 000/80.88ms ∼ 0.1M bps, the utilization on link AB is
   0.1M bps/10M bps = 0.01; on link BC is 0.1M bps/100M bps = 0.001;
   c) the end-to-end bottleneck link is AB with rate of 10Mbps, the highest end-to-end throughput is 10Mbps;
   the minimum window size is 10M/0.1M = 100, the utilization on AB will be 100%, on BC will be 10%.
